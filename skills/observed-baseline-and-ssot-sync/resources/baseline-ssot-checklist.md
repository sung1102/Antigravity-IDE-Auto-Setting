# Observed Baseline & SSOT Sync Checklist（實測仿照與回溯同步檢核清單）
> 若專案已有特定實測規範，以專案 Tier 1 事實基準與使用者明確要求優先。

## 1. 實測行為分析與第一階段仿照（Replicate-First）
- [ ] 是否已取得並核對真實觀察證據（LA 波形 / 示波器 / Sniffer / 實機 Log），而非憑早期猜測文件開發？
- [ ] 第一階段實作是否 100% 還原觀察到的封包內容、位元順序、脈衝次數、發射間隔與等待/避碰視窗？
- [ ] 是否確認**沒有**擅自加入未經實測的阻塞 `delay()`、`FLUSH_RX`、額外釋放包、自動重傳或二階防燙延遲？
- [ ] 是否確認**沒有**擅自刪減實測觀察到的喚醒脈衝、保活心跳、避碰靜默時間或雙階停水延遲？
- [ ] 外層應用變通或安全防護，是否均建立在「不改變底層已驗證時序契約」的前提之上？

## 2. 可疑點與異常流程處理（Suspect-and-Propose）
- [ ] 對於看似多餘或反直覺的硬體/協定步驟，是否已克制「先改再說」衝動，先停留在 `PLAN_ONLY` 提出可疑報告？
- [ ] 可疑報告是否包含單變因對照測試方法與回滾機制，而非同時修改多個時序參數？

## 3. 中途修正後之 SSOT 回溯掃描（Retroactive Sweep）
- [ ] 確認本次修正後，是否已全專案搜尋舊數值、舊封包Hex、舊超時常數、舊狀態機描述？
- [ ] `docs/`、規格包、`config/*.json`、`README.md` 與 `GEMINI.md` 是否已同步至最新 Tier 1 事實基準？
- [ ] 是否已檢查專案內是否存在「同名程式碼複本 / 舊範例檔」與線上正式程式碼產生內容漂移（Drift）？
- [ ] 已過時但需留存的歷史檔案，是否在檔頭明確標示 `[DEPRECATED / HISTORICAL]` 並指向最新 Tier 1 路徑？
- [ ] 本次修正與同步是否未動到不應變更的驗證完成程式碼（若屬純文件/規範清理任務）？
